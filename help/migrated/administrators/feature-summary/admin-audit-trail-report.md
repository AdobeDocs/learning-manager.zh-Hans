# 管理员审查追踪报告 {#adminaudittrailreport}

生成有关对帐户的基本设置、高级设置和集成设置所做的配置更改的报告，包括每次更改的人员、时间以及更改前后的值。

## 报告捕获的内容

管理员审查追踪报告提供配置更改的历史记录，以便您确定：

- 谁进行了更改
- 进行更改的时间
- 更改之前的设置
- 更改后的设置

该报告介绍了对以下方面所做的更改：

- **基础知识**&#x200B;设置
- **高级**&#x200B;设置
- **集成**&#x200B;设置

此报告仅供添加：随着时间的推移会添加新的更改记录，并且永远不会删除以前记录的条目。 这样，您就可以查看跨多个更改的设置的完整历史记录，而不仅仅是查看其当前值。

任何具有报告权限和完全用户组访问权限的用户都可以使用该报告。 这包括已获得报告访问权限的完整管理员和自定义管理员。

>[!NOTE]
>
>从2026年9月的更新112开始，将开始提供相关记录。 报告中不包括本次更新之前所做的更改。 请参阅[发行说明](/help/migrated/release-note/release-notes.md)更新112。

## 为什么此报告对合规很重要

在受监管行业中运营的组织通常需要证明对处理电子记录的系统所做的配置更改会被跟踪、归属和保留。 管理员审查追踪报告通过标识每个变更的人员、设置、时间和前后值来支持这些要求。

>[!NOTE]
>
>此报告支持您组织的合规性活动。 它本身并不证明遵守任何特定法规或标准。

## 生成管理员跟踪报告

1. 以管理员身份登录到Adobe Learning Manager 。
2. 在左侧导航栏中，选择&#x200B;**管理** > **报告** > **自定义报告**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report1.png)

3. 向下滚动并选择&#x200B;**管理员审核记录**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report2.png)

4. **选择范围**：选择要报告的期间 — **上一周**、**最近一个月**&#x200B;或&#x200B;**选择日期**。 如果选择&#x200B;**选择日期**，请输入&#x200B;**开始日期**&#x200B;和&#x200B;**结束日期**。
5. **选择设置类型**：选择&#x200B;**全选**、**基本**、**集成**&#x200B;或&#x200B;**高级**。

   若要查看此报告在基础知识、集成和高级方面跟踪的设置的完整列表，请选择&#x200B;**下载设置列表**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report6.png)

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report3.png)

6. 选择&#x200B;**生成**。

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report4.png)

   ![](/help/migrated/administrators/feature-summary/assets/audit-trail-report5.png)

包含更改的`.csv`文件将下载到浏览器的“下载”文件夹。 生成报告可能需要一些时间 — 您可以在处理报告时继续使用Adobe Learning Manager。 如果在报告准备就绪之前关闭浏览器窗口，则会在您下次登录时开始下载。

## 此报告的常见用途

- **调查意外设置更改** — 确认更改的内容、更改时间和更改者，而不是依赖假设。
- **查看多个管理员所做的更改** — 生成给定时间段内报告范围内的所有配置活动的综合视图，而不是单独联系每个管理员。
- **确认批准的配置更改** — 验证预期的管理员在预期的时间段内进行了更改，并且新值是否与批准的内容相匹配。
- **将设置的历史记录与多个更改进行比较** — 使用&#x200B;**修订**&#x200B;列查看特定设置更改了多少次，并按顺序查看每个记录的值，包括后面的更改是否与之前的更改进行了恢复。
- **支持合规性审查** — 生成审查期间的报告，作为管理和合规性记录的一部分。
- **在策略更改后查看设置** — 确认预期的配置更新已一致应用，并识别任何意外发生的更改。
- **维护历史管理记录** — 根据您组织的记录管理实践下载并保留报告。

## 报告列引用

下载的`.csv`文件包含以下列。

| 列 | 描述 |
|---|---|
| **事件ID** | 此特定更改记录的唯一标识符。 |
| **时间戳(UTC)** | 进行更改的日期和时间，以协调世界时表示。 |
| **电子邮件** | 进行更改的管理员的电子邮件地址。 |
| **UUID** | 进行更改的管理员的唯一标识符。 仅在帐户级别启用UUID时填充。 |
| **管理员名称** | 进行更改的管理员的显示名称。 |
| **事件类型** | 记录的事件类别 — 例如`Modify`、`Create`或`Delete`。 |
| **操作类型** | 对该设置执行的操作的类型 — 例如，`CREATE_SETTING`、`UPDATE_SETTING`或`DELETE_SETTING`。 |
| **对象类型** | 已更改的设置或配置对象。 |
| **对象ID** | 已更改的特定设置或配置对象的唯一标识符。 |
| **上一个值** | 更改前的设置的值。 （对于已删除的设置，这将显示删除之前存在的值。） |
| **新值** | 更改后的设置的值。 （对于已删除的设置，此项为空。） |
| **修订** | 记录事件时此特定对象ID发生更改的次数。 对象的第一次记录的更改从1开始。 |

>[!TIP]
>
>要查找某个时间段内删除的所有设置，请筛选&#x200B;**操作类型**&#x200B;为`DELETE_SETTING`的下载文件。

## 以编程方式访问此报告

您可以使用作业API以编程方式检索管理员审核记录报告，而不是从管理员应用程序手动生成报告。 如果要计划定期导出或将报告提交到下游监控或警报系统，此功能非常有用。 请参阅[作业API管理员审核跟踪报告](/help/migrated/api-changes-sep-2026.md#job-api-for-admin-audit-trail-report)。

## 限制

- **本地化**：报表内容未本地化。 无论帐户配置的区域设置如何，都会以默认帐户语言生成报告。
- **更改原因**：报告未捕获更改的原因。 单独保留任何相关的变更请求、批准或业务理由。

## 最佳实践

- 选择涵盖可疑或计划更改的日期范围。
- 当受影响的设置区域未知时，选择&#x200B;**全选**。
- 比较每个条目的&#x200B;**Previous Value**&#x200B;和&#x200B;**New Value**&#x200B;列。
- 使用&#x200B;**管理员名称**&#x200B;和&#x200B;**时间戳**&#x200B;列将更改与批准的工作或内部记录相关联。
- 当您的组织需要变更的书面说明时，请单独保留相关的变更请求、批准或业务理由。

## 故障排除

**在特定日期之前看不到任何记录**
记录仅在更新112（2026年9月）之后可用。 报告中不包括在更新之前所做的更改。 请参阅[发行说明](/help/migrated/release-note/release-notes.md)

**对于部分或所有记录，UUID列为空**
仅当在帐户级别启用UUID时，才会填充UUID列。 如果未启用，则此列将不存在。

**我具有自定义管理员角色，但找不到此报告**
确认您的自定义角色已被授予报告权限和完整的用户组访问权限。 如果需要，请联系您的帐户所有者或完整管理员以请求此访问权限。
