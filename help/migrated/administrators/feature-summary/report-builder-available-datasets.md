# Report Builder中的可用数据集

## 概述

Report Builder将所有可用列组织到数据集中，称为相关字段组。 本文列出每个数据集，描述其包含的内容，并记下可以在单个报告中组合哪些数据集。

## **可用的数据集**

表中的信息并非详尽无遗。 有关数据集中所有列的完整列表，请参阅&#x200B;**数据集中的列列表**&#x200B;部分。

| **数据集** | **它包含的内容** | **键字段** |
|----------------------------------------------------------|--------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **用户** | 活动和已删除学习者的学习者个人资料数据 | 名称、电子邮件、用户ID、经理、活动字段、状态 |
| **成绩单（学习对象）和成绩单（模块）** | 注册和完成记录 | 注册日期、完成日期、进度百分比、状态 |
| **学习对象** | 课程、学习路径和认证元数据 | 学习对象名称、学习对象ID、类型、目录、目录标签、状态 |
| **学习对象实例** | 具有多个实例的课程的实例级别详细信息 | 实例名称、实例ID、注册限制、截止日期 |
| **目录** | 目录元数据和目录标签键值对 | 作者姓名、创建日期、持续时间、格式。 **目录标签列是客户配置的**。 仅当您的帐户设置了目录标签时，才会显示这些标签。 您看到的标签名称和值将反映您自己的配置。 |
| **用户组** | 用户组成员资格和层次结构 | 创建日期、成员计数、名称、状态 |
| **模块** | 教室、虚拟教室和电子学习模块的会话详细信息 | 模块ID、讲师姓名、开始时间、结束时间、位置 |


>[!NOTE]
>
>对于通过目录共享从其他帐户获取的课程，学习对象数据集中的&#x200B;**作者姓名**&#x200B;列会返回源帐户中的原始作者姓名。 这与标准的ALM管理界面和固定报告不同，在固定报告中，获得的课程会显示“外部作者”。 此行为特定于Report Builder，仅适用于配对（接收）帐户。

## 数据集如何连接在一起

并非每对数据集都可以合并到单个报告中。 数据集必须在Adobe Learning Manager的数据模型中共享一个逻辑关系才能连接。 添加第一列时，Report Builder会筛选剩余的数据集，以仅显示兼容的数据集。 如果数据集显示为灰色，则它不能与您已经选择的列直接联接。

这意味着数据集不能与您已经选择的列连接。 这是数据模型中的硬约束。 两个数据集不共享兼容的联接路径。

一个常见的示例是&#x200B;**合规性%**&#x200B;派生字段。 选择合规性%时，将禁用&#x200B;**转录文本**、**模块转录文本**&#x200B;和&#x200B;**学习对象实例**&#x200B;数据集。 合规性%根据学习对象和目录在用户或用户组级别进行计算。 它只能与&#x200B;**用户**、**用户组**、**学习对象**&#x200B;和&#x200B;**目录**&#x200B;列和筛选器一起使用。

要使用禁用的数据集，请取消选择导致冲突的列，然后添加所需的数据集。

>[!NOTE]
>
>如果生成的报告包含课程数据但不包含学习路径数据，请检查您是否已将学习对象数据集与模块数据集联接在一起。 模块直接链接到课程，而不是直接链接到学习路径。 因此，如果包含“模块”字段，Report Builder可能仅返回课程记录并筛选出学习路径。 要报告学习路径，请避免添加模块字段，除非报告专门用于分析课程级别的模块数据。

下面的连接关系是从Report Builder数据模型绘制的。 了解它们有助于您在构建报告之前规划要合并的数据集。

### 中心数据集

两个数据集作为中心中心。 大多数其他数据集通过它们连接：

* **注册**（注册数据集），主事实表。 它直接连接到&#x200B;**用户**（注册的学习者）、**学习对象**（他们注册的内容），并通过学习对象连接到&#x200B;**模块**、**目录**、**目录标签**&#x200B;和&#x200B;**学习对象实例**。
* **模块转录**（模块转录）数据集 — 模块级别进度事实表。 它连接到&#x200B;**用户**&#x200B;和&#x200B;**模块**，后者又链接到&#x200B;**学习对象**。

合并学习者、课程和完成数据的大多数报告都是通过这两个中心之一构建的。

### 锯齿关系

数据模型中的某些字段通过命名角色（而不是直接学习者ID）加入&#x200B;**用户**&#x200B;实体。 这些是带锯齿的外键。 它们指向同一个用户表，但表示不同的角色：

* **讲师**：模块作为会话的讲师加入用户
* **作者**：学习对象作者作为学习对象的作者加入用户
* **经理**：用户自行加入以代表学习者的经理
* **完成者**：注册和模块成绩单各带有单独的“完成者”用户引用

因此，一份报告可以同时显示学习者姓名及其讲师姓名。 它们都来自用户实体，通过不同的连接路径。

### 用户组数据集类型

**用户组**&#x200B;类别包含多个不同的数据集视图，每个视图都覆盖不同类型的组：

| **数据集** | **组类型** |
|---------------------------------------------------------|---------------------------------------------------------------|
| **用户组** (userGroup) | 所有用户组。 将其用作主要用户组数据集 |
| **用户组（活动字段）** (active_field_user_group) | 基于活动字段值的组（例如地区、部门） |
| **用户组（团队）** (team_user_group) | 基于经理层次结构的组 |
| **用户组（自定义）** (custom_user_group) | 手动配置的自定义组 |
| **用户组（内置）** (inbuild_user_group) | 系统定义的组 |

基于视图的用户组数据集（**活动字段**、**团队**、**自定义**、**内置**）在架构中没有直接的外键关系，它们是SQL视图。 这意味着它们的连接约束比核心&#x200B;**用户组**&#x200B;数据集宽松。 在将用户组数据与注册或转录数据联接时，使用核心&#x200B;**用户组**&#x200B;数据集可获得最可靠的结果。

## 派生字段

派生字段是按Report Builder计算的预计算列。 它们与列选择器中的标准列分开列出。

| **派生字段** | **它计算的内容** | **所需的数据集** |
|-------------------------|-------------------------------------------------------------------------|-----------------------------------------|
| **符合性%** | 完成带有合规性标记的课程且必修的学习者百分比 | 用户组、学习对象、成绩单 |
| **完成%** | 完成数除以注册数x 100 | 成绩单或学习对象 |
| **注册用户数** | 某个学习对象的已注册学习者总数 | 学习对象 |
| **完成计数** | 学习对象的总完成数 | 学习对象 |
| **开始计数** | 已开始但未完成的学习者 | 学习对象 |
| **个成员计数** | 用户组中的用户数 | 用户组 |
