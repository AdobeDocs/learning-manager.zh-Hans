# 在Content Composer中编写有效提示

了解如何在Content Composer的每个阶段编写有效提示，从打开提示到简介、大纲和课程编辑器，以用更少的编辑生成准确、结构完善的AI生成课程。

内容书写器全程是对话式的。 每个阶段所生产的产品的质量取决于你所给产品的质量。 本指南介绍了如何在&#x200B;**主页**、**简介**、**轮廓**&#x200B;和&#x200B;**课程**&#x200B;这四个阶段中的每一个阶段与AI进行有效通信。

## 阶段1：主页 — 编写打开提示

开头提示是您的起点。 它不必完美。 内容撰写器会读取您的提示并使用它打开对话。 即使是粗略的提示也会使流程移动；助理会在简要阶段询问后续问题，以补充缺少的内容。

话虽如此，更具体的提示意味着AI会更准确地预填摘要，从而减少生成轮廓之前的反复输入。 如果您对受众、标题和目标有清楚的了解，请在提示中注明这些信息。

### 内容合成器预计会出现什么情况

Content Composer需要满足以下条件：

- **课程的内容是什么**？ 用一两句描述主题区域。 这会成为课程标题。
- **哪些人**&#x200B;是学习者？ 命名他们的角色和体验级别。 该图层成为学习者个人资料。
- **学习目标是什么？** 描述您希望学习者在完成课程后完成的结果或行为更改。 这成为《简介》中的学习目标。

### 有效提示的剖析

**[学习者+体验级别]** + **[特定标题]** + **[学习目标]**

有效的提示有三点：它描述了课程的内容、适用对象以及学习者在完成课程后应该做的事情。

**示例**：

我想为新销售代表创建一门课程，介绍我们的企业定价级别和折扣审批工作流程。 最终，他们应该能够自信地处理客户最常见的三个异议。

分解为：

- **标题：**&#x200B;面向新销售代表的企业定价、折扣审批和处理客户异议课程
- **学习者：**&#x200B;在前90天成为新销售代表且熟悉企业定价结构
- **目标：**&#x200B;使用批准的消息传递框架自信地处理最常见的三个客户异议

选择“**开始使用**”后，内容编辑器将打开“**简介**”阶段。 在生成大纲之前，查看AI根据提示生成的预填充字段、标题、学习者配置文件和目标，并优化任何与您的意图不匹配的内容。

### 有或没有有效的提示

| 包括 | 避免 |
|---|---|
| 清晰的课程标题或主题区域 | 模糊的主题（“关于安全的内容”、“一般培训”） |
| 学习者的角色或人员构成（“新销售代表”、“一线仓库员工”） | 广泛的受众（“所有员工”、“所有人”、“用户”） |
| 学习者的经验水平（“职业生涯早期”、“熟悉X但不熟悉Y”） | 假设AI知道观众的背景 |
| 学习者当前苦苦挣扎或不了解的内容 | 正在跳过学习差距。 人工智能使用它们来塑造词汇和情景 |
| 明确的学习目标 — 学习者在课程结束后能够执行的操作 | 一般目标（“向他们传授X的一切”，“涵盖所有方面”） |

## 阶段2：简介 — 锐化AI的建议

提交提示后，Content Composer会打开“简要”阶段并预填三个字段：课程标题、学习者配置文件和学习目标。 AI会询问后续问题，以在生成轮廓之前锐化每个字段。

这是一个对话阶段。 您对AI问题的回答质量直接决定了其生成的大纲的质量。

### 课程标题

AI会根据您的提示预填课程标题。 审阅并选择适合的文档，键入您自己的文档，或描述您想要的内容：

“都不是。 本课程专门针对审批工作流程，而不是一般定价。”

### 学习者配置文件

AI会询问相关角色、经验水平以及学习者目前难以应对的问题。 要具体说明他们知道和不知道什么：

| 不太有用 | 更有用 |
|---|---|
| “所有员工” | “职业中期的软件开发人员熟悉灵活而又没有企业安全合规经验” |
| “此主题新手” | “早期职业经理从个人投稿人职位晋升而来，没有接受过正式的管理培训” |
| “我们的销售团队” | “新客户经理在刚上任的90天内，对CRM工具非常熟悉，但对企业定价结构并不熟悉” |

### 学习目标

AI会询问学习者在完成课程后能够执行哪些操作。 这是最重要的“简短”字段 — 它控制AI在源文件中为哪些内容设置优先级、如何构建大纲以及测试内容。

将目标编写为以操作动词开头的行为：

| 弱目标 | 强烈目标 |
|---|---|
| “了解数据保护” | “使用组织的报告流程识别个人数据、应用正确的存储和共享惯例并报告可疑的违规情况” |
| 了解异议处理 | “使用获批准的消息传递框架回应最常见的三个客户异议，而不升级至销售总监” |
| “了解入门培训流程” | “完成第一周入门培训清单，提交所需的合规表，并在没有IT协助的情况下访问发挥其作用所需的工具” |

>[!IMPORTANT]
>
>**生成大纲之前：**&#x200B;大纲完全从“简介”生成，而不是从原始提示生成。 在选择“**生成大纲**”之前，请确认标题是面向学习者的，学习者配置文件指定特定的角色和经验级别，学习目标描述可衡量的在职行为。 定义明确的Brief可生成结构明确的轮廓。 如果仍有领域感觉一般，请立即对其进行优化。  这样可节省以后的重要编辑工作。

你总是在掌控局面。 Content Composer将提出后续问题以帮助完善Brief，但由您决定每个字段的内容。 定义明确的Brief可生成结构明确的轮廓。 输入的内容越具体，以后所需的编辑就越少。

### 签署这份简报需要更多工作

- 学员档案显示，“想要了解X的员工”，而不是指定具体的角色和经验水平
- 学习目标描述主题领域，而不是可衡量的在职行为
- 标题含糊（“IT安全”），而不是面向学习者的结果（“识别并响应网络钓鱼尝试”）

## 阶段3：大纲 — 通过对话编辑

确认Brief之后，Content Composer会生成课程和主题结构。 在生成完整课程之前，您可以通过聊天面板查看课程并请求更改内容。

在当前版本中，轮廓编辑完全是对话式的。 无法在画布上选择课程或标题进行重命名或重新排序。 通过键入纯语言请求进行所有更改。

这也是进行结构性改革的最有效阶段。 编辑大纲需要几秒钟时间。 重组生成的课程需要更长的时间。

### 如何对大纲编辑请求添加短语

直截了当而且明确具体。 按当前标题命名课程，描述所需的更改，并可选择说明原因。

**重命名：**

- “将第1课重命名为‘网络钓鱼攻击的运作方式’。”
- “将标题2.3重命名为‘升级路径和时间轴’。”

**添加：**

- “在第2课中添加有关QR码钓鱼的新主题。”
- “第4课后添加有关事件响应的课程。”

**移除：**

- “删除主题1.3。”
- “删除第5课。 相关内容将在单独的课程中介绍。”

**重新排序：**

- “把第三课移到第二课。”
- 将主题2.1移到第2课的结尾。

**拆分：**

- “第3课分为两课，一课涵盖垃圾邮件过滤器，一课涵盖修补程序管理。”

**合并：**

- “将第4课和第5课合并到名为‘事件响应和恢复’的单个课程中。”

**重新生成：**

- “重新生成大纲，更加注重密码卫生和MFA。”
- “重新生成大纲 — 目前的结构对于非技术性受众来说太技术性了。”

### 大纲阶段无法执行的操作

- 层次结构已固定为“课程”>“主题”。 不能创建子主题或三层结构。
- 您无法在此阶段添加组件或媒体。 这些内容会添加到课程编辑器中。

## 阶段4：课程 — 通过助理优化内容

批准大纲并生成课程后，**“使用内容书写器创建”**&#x200B;面板在屏幕右侧保持打开。 您可以通过对话使用该功能来优化、扩展或调整所生成课程的任何部分。

课程编辑器中的助理适用于内容编辑任务。 对于产品操作方法问题，请使用此帮助文档而不是询问助手。

### 如何对课程编辑请求添加短语

**重写或调整特定部分：**

- “改写第一课第二节中的段落，使其更简洁 — 目标定三句。”
- “使主题2.1中的内容不那么具有技术性。 观众没有IT背景。”
- “在第1课的介绍中添加一个实际示例。”

**调整色调：**

- “以更具对话性的语气重写第二课。”
- “使主题3.2中的内容更具权威性 — 这是合规性课程。”

**展开或添加内容：**

- “请在主题1.3中添加基于情景的示例，展示网络钓鱼电子邮件的外观。”
- “展开MFA部分，使其包含在移动设备上设置它的说明。”

**减少或简化：**

- “将幻灯片5上的文本缩短为三个项目要点。”
- “将专题2.2第二段概述为一句。”

**调整测验：**

- 重新生成第2课的测验，提出更棘手的问题。”
- “将问题3替换为一个基于情境的问题，即如何识别社会工程手段的尝试。”
- “在第1课测试中，我们还要再添加两个主要关于MFA设置的问题。”

**调整图像：**

- “将主题2.2中的图像替换为显示社会工程学场景的图像。”
- “为主题1.1生成图像，在笔记本电脑屏幕上展示网络钓鱼电子邮件。”

**添加或修改组件：**

- “在主题3.1中添加一个包含三个定价层定义的翻转卡。”
- “通过升级步骤为主题2.3添加一个折叠式面板 — 每个步骤一个面板。”
- 将主题1.2中的项目符号列表转换为时间轴组件。

### 课程助理无法执行的操作

- 直接在画布上重命名课程或主题。 使用助手：“将第2课重命名为‘密码安全’。”
- 创建分支路径或自适应路径。 课程结构是线性的。
- 添加新的经验或调整大纲。 结构变化需要返回到“大纲”阶段。

## 跨所有阶段的最佳做法

- **在打开内容书写器之前说明要生成的内容。** 预先拟定的句子在输入域的压力下往往比键入的句子更清晰。
- **在学习目标上投入时间。** “简介”中的目标控制大纲结构、源文件优先顺序和测验对齐方式。 特定的、以行为为中心的目标可减少后续每个阶段的编辑。
- **在生成大纲之前细化摘要。** 大纲是从“简介”构建的，而不是从原始提示构建。 一份明确定义的摘要，其中含有特定的学习者配置文件和学习目标，可生成结构化的相关大纲。
- **在生成课程之前编辑大纲。** 大纲阶段的结构更改需要几秒钟时间。 课程生成后相同的更改需要更长的时间。
- **使用课程助理获取内容而不是结构。** 结构更改、添加课程、重新排序主题都属于“大纲”阶段。 使用“课程助手”可以优化文本、色调、示例和测验问题。
- **在每个请求中都要具体。** 命名您要更改的课程、主题、幻灯片或问题。 “让一切变得更美好”不会给人工智能带来任何可操作的东西。 “使主题2.1更简洁，并添加一个现实世界的示例”。
